PeopleDesk

Design proposal for the HR system. Click through the screens, then tell me what to change or confirm. Nothing is built yet and all data shown is sample data.

Draft for confirmation

A web HR system for managing employees, their contracts and pay rate, attendance pulled from ZKTeco devices, and the lookup lists behind them. Built with Next.js, shadcn/ui, PostgreSQL and lucide icons.

Login

Email and password, session cookie, role-based access. Admin creates users, no public sign-up.

Employees

Paged list with No, Employee, Designation, Department, Joining Date, Contract, Rate and Status. Advanced filter, import, export, profile picture.

Attendance sync

ZKTeco devices registered in the system. Mock adapter first, real device connection later without changing the screens.

Masterdata

Departments, designations, contract types, statuses, locations, shifts and holidays maintained in one place.

Settings

Company profile, users and roles, attendance rules, employee numbering, import templates.

Extras (your call)

Leave, contract expiry alerts, org chart, documents, audit log, payroll prep. See the Proposed extras tab.

Technical approach

Stack

  • Next.js 15, App Router, TypeScript
  • shadcn/ui, Tailwind, lucide-react
  • PostgreSQL with Prisma
  • Auth.js (credentials) with bcrypt

Lists and files

  • TanStack Table, server-side paging and filters
  • Filters kept in the URL, so views can be shared
  • ExcelJS for .xlsx import and export
  • Photos on local disk or S3, switchable by env

Attendance

  • Device adapter interface with a mock now
  • Raw punches stored, then turned into daily records
  • Real option later: device pushes to us (ADMS) or we pull (node-zklib)

List

  • No is the row number on the current page, separate from the employee ID.
  • Paging, sorting and filtering run on the server, so it stays fast at thousands of rows.
  • Page size 10, 25, 50, 100.
  • Row menu: View, Edit, Change status, Delete (soft delete).

Advanced filter

  • Multi-select for department, designation, contract, status.
  • Ranges for joining date and rate.
  • Active filters show as removable chips.
  • Save a filter as a named view.

Import and export

  • Export downloads .xlsx or .csv of the current filtered result, or the selected rows.
  • Import uses a downloadable template, validates every row first, shows errors per row, then commits.

How the mock works

  • A mock device generates realistic punches for your sample employees.
  • Sync button, schedule, log and unmatched-PIN handling are all real.
  • Swapping to a physical device means writing one adapter, no screen changes.

Real device options

  • Push (ADMS): device posts punches to our server. Best for many sites.
  • Pull: server connects to the device IP on port 4370. Needs network reach to the device.

Next step after sync

  • Punches become daily records: first in, last out, late, early, absent.
  • Shifts from masterdata drive those rules.

The answers shape the build. My default is in bold, so a quick “go with defaults” is a valid reply.

01
What does “Rate” mean?

Default: an amount plus a basis (per month, per day, per hour) so monthly staff and daily workers fit the same column. Alternatively a single monthly salary only.

02
“No” column

Default: row number on the page. Alternative: the employee ID shown as No.

03
Who uses it, and with which roles?

Default: Admin, HR, Manager, Employee as on the Settings screen. Tell me if you only need Admin and HR.

04
Languages and currency

Default: English interface, Khmer name field on the profile, USD with optional KHR. Full Khmer UI can be Phase 3.

05
ZKTeco model and network

Default: mock now. For the real step I need the device model, how many sites, and whether devices can reach a server (push) or the server can reach them (pull).

06
Import and export format

Default: .xlsx with a template, plus .csv export.

07
Hosting and email

Default: runs on a local PostgreSQL and photos on disk. For password reset emails I need an SMTP account later.

08
Visual style

Default: the clean shadcn look shown here, teal accent, light and dark themes. Share a brand colour or logo to use instead.
